# Document Search Base Assistant – Setup Guide

A local, demo‑ready **company‑wide knowledge base assistant** that can search engineering documentation, policies, onboarding guides, and internal FAQs.

Local Demo: https://drive.google.com/drive/folders/1aSpfwZdBt-bfd77DK2TmJvcu-iYxA4Zq?usp=sharing


## Features

- **Full‑text search** over documents with metadata filters (department, role, tags)
- **Role‑based access control** – only documents permitted for the requesting role are returned
- **Incremental indexing** – add or update documents without rebuilding the whole index
- **Document versioning** – each document stores a version number and timestamps
- **Auditing** – every query is logged with user, role, timestamp, and response size
- **Caching** – LRU cache for recent queries to speed up repeated searches
- **Observability** – Prometheus metrics endpoint exposing request latency, cache hits/misses, and document counts
- **Dockerised** – easy to run locally or in a container for demos

## Quick start (local)

```bash
# Clone the repo (once we push it) or copy the project directory
cd enterprise_kb_assistant

# Create a virtual environment
python3 -m venv venv
source venv/bin/activate

# Install dependencies
pip install -r requirements.txt

# Initialise the SQLite database (creates tables)
python -m app.indexer init

# Run the API (development mode)
uvicorn app.main:app --reload --port 8000
```

The API will be available at `http://localhost:8000`.  Swagger UI can be accessed at `http://localhost:8000/docs`.

## Docker demo

```bash
docker build -t enterprise-kb-assistant .
docker run -p 8000:8000 enterprise-kb-assistant
```

## API overview

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/search` | `GET` | Search documents. Parameters: `q` (query), `department`, `role`, `tags` (comma‑separated). |
| `/index` | `POST` | Add or update a document. Body: `title`, `content`, `department`, `role`, `tags` (list). |
| `/metrics` | `GET` | Prometheus metrics (for observability). |

## Development notes

- **Embedding model** – uses `sentence-transformers/all-MiniLM-L6-v2` which runs locally and provides decent semantic search.
- **Search engine** – SQLite FTS5 + cosine similarity on embeddings.
- **Authentication** – For demo purposes, role is passed as a query parameter. In production replace with proper auth (e.g., OAuth2 + JWT).
- **Logging/Auditing** – All queries are written to `audit.log`.
